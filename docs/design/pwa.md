# PWA: основа клиента

Каркас Task 1 работает как статическое SPA: SvelteKit 2, Svelte 5 с runes, adapter-static, `200.html` для глубоких ссылок. Сервер Node нужен только локальному тестовому edge. Начальная страница пока обозначает место списка сессий. Task 3 добавляет независимые автоматы синхронизации и FakeHub; HTTP-клиент и service worker относятся к другим задачам плана 1.3b.

## Токены и форма

`web/src/lib/styles/tokens.css` начинается с побайтной копии утверждённых токенов макетов. После `/* pwa additions */` находятся дополнения платформы и motion-токены макета 23. Макеты не нужны для сборки и CI. Тест сравнения исходной части пропускается, когда локальные макеты отсутствуют.

Тёмная тема по умолчанию: бирюзовые поверхности, аквамариновый акцент, системный шрифт с поддержкой русского без сетевых запросов. Светлая тема использует утверждённую мятную палитру. Радиусы различают pill-контролы, круглые иконки, карточки и верхние углы панелей. Полосы и декоративные тени не используются. Контуры точек StageTrack взяты из макета 23; четыре точечных исключения `raw-shadow` объяснены в `token-lint.allow.json`.

Матрица AA проверяет каждый заданный в brief текстовый цвет на каждой указанной поверхности в обеих темах. Исходный `--time` не проходит на selected (около 3,94:1 в тёмной и 4,12:1 в светлой теме). Дополнение переопределяет только этот цвет значением соответствующего `--muted`; исходная копия остаётся неизменной.

## Тема и движение

`theme` экспортирует `pref`, `effective`, `set` и `toggle`. Предпочтение сохраняется в `canterlot.theme`; `system` следит за ОС. Внешний блокирующий `/theme-init.js` до отрисовки выставляет `html[data-theme]`; после загрузки модуль синхронизирует `meta[name=theme-color]` с вычисленным `--bg`. Переключение темы не анимирует все цвета. Отказ localStorage оставляет выбор темы работоспособным в памяти.

Публичные `--duration-*` вычисляются через один `--motion-scale`: 0, 0.5, 1, 1.5. `setMotionScale` применяет значение на устройстве; интерфейс настроек и сохранение скорости относятся к Task 9b. Системный reduced motion имеет приоритет. `durationMs` читает вычисленную длительность через CSSOM (включая `calc`); кольцо обратного отсчёта анимируется линейно за реальное оставшееся время и не масштабируется через `--motion-scale`. При выключенном движении CSS и WAAPI статичны. Никаких таймеров продвижения этапов в StageTrack нет.

StageTrack принимает `stages: {id,label,kind?}[]`, `index`, `state`, `form: compact | named`, доступное имя `label`, необязательные `status`, `reason`, `progress` и `countdown: {from,durationMs}`. Внешний потребитель меняет index только по событиям хаба. Pulse означает ожидание другой стороны, spin работу canterlot. Ring показывает долю переданных байтов или заданный срок сброса. Последний этап статичен после однократного приземления; «агент работает» не крутится, итоговая подпись доставки «доставлено» передаётся через status. Геометрия, заполнение линии, кольцо, halo, кривые и смена подписи перенесены из утверждённого макета 23. Быстрая смена подписи сохраняет последнее значение; выключение движения отменяет текущую WAAPI-анимацию.

Динамическая геометрия устанавливается через `style.setProperty`, без создания style-атрибутов из строк. Сырые стили не допускаются и в значениях action: используются только токены либо структурные проценты/доли и SVG-координаты.

## Примитивы и доступность

`Button` требует текстовую reason при disabled на уровне TypeScript, показывает причину и связывает её через aria-describedby. `IconButton` требует доступное имя и имеет цель не меньше `--target`; Icon использует локальный SVG-реестр. В реестре иконок нет иконки `check`; статус передаётся словами, цветом и StageTrack. Текстовых glyph-галочек и emoji в интерфейсе нет.

Pill, Mark используют шесть ColorKey; Toggle нативный checkbox с role switch; Segmented нативные radio в подписанной группе. Field связывает label, hint и error с полем; Select и Textarea используют Field. Gauge ограничивает значение диапазоном 0..100 и имеет role meter. Disclosure использует details/summary. TopBar и BottomNav воспроизводят плавающие поверхности макетов.

Sheet использует модальный dialog, aria-modal, inert фона, цикл Tab/Shift+Tab, Escape и восстановление фокуса. routeKey добавляет shallow history entry SvelteKit; Back закрывает панель без изменения прокрутки. ConfirmDialog использует ту же механику. Во всём приложении один host live region; announce объединяет одинаковый текст за две секунды. StageTrack объявляет только смену этапа/фазы, а не байтового прогресса. Есть skip link и заметный focus-visible.

## Проверки и CSP

`bash scripts/check-web.sh`: npm ci, svelte-check без предупреждений, ESLint, token lint, Vitest, production build и UI Playwright в Chromium и Firefox. Общий лимит UI workers 2, stack workers 1; desktop Firefox имеет дополнительный предел 1 worker из-за лимита процессов среды (два экземпляра приводили к EAGAIN и падению content-процессов). На общей VM скрипт по умолчанию ограничивает внутренние пулы Tokio, Rayon и Firefox TaskController двумя потоками; GSettings использует память, без записи в домашний каталог. Browser preferences и sandbox не меняются. `--stack` запускает будущий real-hub suite Task 10; пока real-hub fixtures не реализованы. Проверки Rust (`scripts/check.sh`) и браузерные (`scripts/check-web.sh`) не запускаются одновременно. Ниже 5 ГБ свободного места скрипт останавливается с BLOCKED.

ESLint запрещает eval, console.log, HTML sinks и `{@html}` вне единственного будущего renderer. Локальное правило требует label у IconButton. Token lint сканирует CSS, style-блоки, inline стили, SVG paint и строковые цвета TypeScript. Отдельные правила проверяют цепочки длительностей до scaled-токенов и отсутствие emoji/галочек. Исключение обязано иметь причину. Тесты содержат отрицательные примеры каждого правила.

`web/csp.mjs` служит единственным источником CSP для SvelteKit, тестового edge и Caddy. SvelteKit использует hash mode. В закреплённом Kit 2 встроенный announcer генерируется с inline style и вторым live region. Узкий markup-preprocessor `scripts/kit-announcer.mjs` удаляет только этот блок из `.svelte-kit/generated/root.svelte`; приложение объявляет смену страницы через afterNavigate в своём единственном polite host. Тест и явная ошибка при изменении структуры генератора защищают эту интеграцию. Заголовок edge содержит hashes inline-bootstrap из актуального `200.html` и конкретный локальный WebSocket origin, остальные источники закрыты. Production заголовок печатает `node web/scripts/print-csp.mjs https://<хост>` после каждой сборки; универсальные `unsafe-inline`, `unsafe-eval`, `ws:` и `wss:` не разрешены.

Тестовая страница `/__test/primitives` доступна только в сборке с `VITE_UI_TESTS=1` (её включает check-web.sh). Обычная сборка не показывает тестовые контролы. Стенд проверяет фокус, Back, клавиатуру, ширины 320/360 и 200 % текста, оба оформления, реальный progress, reduced motion и отсутствие CSP violations.

## Синхронизация

`sync/wire.ts` переэкспортирует только сгенерированные `ClientOp`, `ServerOp` и `WireEvent` (как `HubEvent`). Номера последовательности сравниваются через BigInt; курсоры остаются десятичными строками в памяти. Неизвестные операции и повреждённый JSON игнорируются. Версия события, отличная от 1, останавливает все области и соединение в `incompatible` с объявлением «Обновите приложение для продолжения».

`BrowserSocket` получает функцию URL: вызывающая сторона строит WSS URL по полю `ws.path` ответа `GET /api/v1/config`; подпротокол всегда `canterlot.v1`. Один `ConnectionManager` обслуживает до 16 областей. `subscribe(scope, applier)` возвращает читаемые через runes `status` и `cursor`, а также `release()`. Повторная подписка на ту же область использует прежний applier; последнее освобождение удерживает область ещё 30 секунд. В `sync/state.svelte.ts` находятся небольшие реактивные объекты; сетевые автоматы сами не зависят от компонентов. Для последующих задач это общий вспомогательный модуль в каталоге Task 3, API-каталог Task 2 не затронут.

`ScopeApplier` связывает автомат с HTTP и reducer: `loadSnapshot`, `applySnapshot`, `fetchRange(after, limit)`, `applyEvents(AppliedEvent[])`. Снимок устанавливает границу B; подписка всегда получает новый `s<n>` и `after:B`. Кадры старых ID отбрасываются. При обрыве сохраняется принятый курсор, новый сокет подписывается с него. Асинхронные ответы диапазона проверяют поколение автомата и не применяются после обрыва, остановки или нового снимка.

Единственное принятие события проверяет непрерывность диапазона. Повтор не достигает reducer; частичное пересечение проходит один раз с `overlap:true`, чтобы Task 4 пометила блок stale и загрузила его целиком. Разрыв буферизуется по началу диапазона и восстанавливается порциями по 256 исходных событий. Предел буфера: 5 000 событий либо 8 МиБ сериализованных данных; превышение требует снимка. `hidden` двигает курсор и ledger без вызова reducer. Для `oversized` автомат получает исходное событие через `fetchRange(scope_seq-1, 1)` до продвижения курсора: это тот же аутентифицированный HTTP-маршрут из href, без перехода по произвольному URL. Retention при такой загрузке также переводит автомат к снимку.

Resync сначала отправляет unsubscribe, затем загружает снимок и подписывается с его границы. Второй resync за 60 секунд ждёт backoff, третий переводит область в `degraded` с повтором через 30 секунд. Это не перезапускает соединение. Первый `lagged` сохраняет собственный курсор клиента, второй за 60 секунд требует снимка; закрытие сервером восстанавливает остальные области независимо. `forbidden` терминален для области, превышение числа подписок отображается как `degraded` без переподключения.

Backoff: 250 мс × 2ⁿ с jitter ±30 %, итоговый предел 15 с; 30 секунд устойчивой связи сбрасывают счётчик. Код 4401 и кадр reauth обходят backoff. Два подключения без open вызывают переданный `probeAuth()` (`GET /api/v1/me`): истёкшая сессия останавливает попытки до `probe('manual')`, недоступность даёт `offline`. Объявления идут через существующий live region только при смене фазы, без текста сообщений.

При видимой странице ping отправляется каждые 25 секунд. Отсутствие pong 5 секунд или любого кадра 45 секунд восстанавливает сокет. `browserLifecycle` следит за visibility, BFCache pageshow, freeze/resume, online/offline и разницей настенных и монотонных часов раз в секунду. После сна дольше 5 секунд, BFCache, resume, online или скачка времени probe ждёт pong не более 2 секунд. Живой сокет и курсоры остаются прежними; сокет без ответа заменяется. Подписки и курсоры не сохраняются в хранилище: выгруженная Android вкладка начинает со снимка.

`FrameBatcher` сохраняет порядок и вызывает reducer один раз за flush кадра. Первая порция консервативна; следующие рассчитываются по измеренной цене события, бюджету 8 мс и минимальной оценке 0,05 мс. `costMs` позволяет reducer передать верхнюю оценку стоимости; неделимое отдельное событие может занять весь кадр. На скрытой странице используется таймер 0, pagehide и dispose синхронно опустошают очередь. Dispose закрывает сокет, освобождает подписки, RAF, таймеры и lifecycle listeners.

`perf/probe.ts` включается только чтением `canterlot.probe=1` либо `?probe=1`; сам модуль ничего не сохраняет. `window.__canterlot_probe` предоставляет счётчики, метрики и ledger без содержимого событий. Ledger проверяет разбиение `1..head`, включая скрытые диапазоны, merged, range, refetch и снимки. Возраст merged считается от `committed_at_from`. Отключённый probe ничего не записывает.

`testing/fake-hub` исполняет опубликованный контракт и проверяет события и кадры через Ajv 2020-12. Журнал каждой области остаётся при restart; неизвестные клиенту виды становятся пустыми hidden. Merger учитывает соседство, область, разговор, исполнение, блок, ревизии, 25 мс и 64 КиБ полного JSON-кадра. Окно WSS считается по поступлению в pump, включая hidden; на дедлайне диапазон уже выпущен. Старые committed timestamps не мешают объединению при replay. HTTP объединяет только hidden, без временного окна. У FakeHub есть контроль retention, обе причины resync, 16 подписок, lagged с закрытием, 4401 и oversized. Известные разговоры создаются через append/snapshot/setSnapshot; чужой ID получает forbidden.

`FakeClock` предоставляет таймеры, RAF и seeded RNG. Chaos изменяет доставку событий (drop, duplicate, reorder, delay), рвёт соединения и сохраняет журнал при restart. Blackhole применяется к текущим сокетам, моделируя зависшее соединение; вновь открытый сокет работоспособен. `hub.routes` регистрирует HTTP-обработчики по пути либо ключу `METHOD /path`. Playwright wire перехватывает `/api/v1/ws` и `/api/v1/**`; smoke-страница находится только в `e2e/edge/fixtures`, edge отдаёт её по `/__fixtures__/ws-smoke.html`, в production build её нет.

Проверки Task 3 включают 300 seeded chaos-прогонов по 200 событиям (не менее 10 % скрытых) с побайтной сверкой текста и чистым ledger, повторяемые три раза; сон 10 минут и 40 пропущенных событий; backlog 1 000 событий; граничное пересечение 103–110 при курсоре 105; resync guard; HTTP oversized; отсутствие оставшихся таймеров; браузерный smoke в Chromium и Firefox.

## Операции и черновики

Журнал `OpJournal` пишет `input`, `scheduled` и `create_conversation` в IndexedDB до того, как запрос уходит. Повтор идёт тем же ключом идемпотентности. Ответ 2xx оставляет операцию `committed`, пока серверный элемент с этим ключом не придёт в `settle`. Конверт с `retry`, отличным от `safe_same_key`, переводит операцию в `refused`: текст возвращает вызывающий код, а не журнал. `NetworkError`, ответ без конверта, таймаут, обрыв и `safe_same_key` оставляют `unknown` и повторяются с паузой от 1 до 30 секунд, сразу после `online` и после восстановления сессии. `AuthRequired` операцию не завершает: пока `session.state` равен `expired`, повторы стоят и продолжаются тем же ключом после следующего успешного `GET /me`. `idempotency_conflict` показывается и не повторяется.

Черновик лежит по ключу `drafts/<owner>/<conversation>`. Запись откладывается на 250 мс и сбрасывается при `visibilitychange: hidden`, `pagehide`, `freeze`, уходе фокуса из композера (`watchComposer`) и уходе со страницы (`leave`). `flushSync` на `pagehide` кладёт одноразовое зеркало в `localStorage['canterlot.draft-tail.<conversation>']`, если транзакция IndexedDB не успеет. `load` берёт более новую копию и удаляет зеркало. Худшее окно между последним нажатием и устойчивой записью равно задержке плюс одна транзакция IndexedDB; `DraftStore.lag.lastMs` и `lag.maxMs` измеряют это окно.

Смена владельца удаляет его IndexedDB, кэши и зеркала черновиков. `canterlot.theme` и `canterlot.enter` остаются: это анонимные настройки, не данные владельца.

## Загрузка вложений

`UploadManager.add` до хеширования отклоняет пустой файл, файл больше `max_attachment_bytes` (104 857 600, точный размер принимается) и одиннадцатый файл в одном сообщении. Причины: «Файл пустой», «Файл больше 100 МиБ», «Не более 10 файлов в одном сообщении». Имя сокращается до последнего компонента пути и 255 байт. Дальше: хеш в воркере слайсами по 1 МиБ, `POST /attachments` с сохранённым ключом, `HEAD` для `Upload-Offset`, `PATCH` слайсами через XHR (`Upload-Offset`, `X-Canterlot-Client`, `X-Correlation-Id`, Origin браузера, без `Idempotency-Key`), `POST …/complete`. Размер слайса берётся из `upload_chunk_bytes` (`GET /config`, 8 МиБ). `409 offset_mismatch` сдвигает смещение по заголовку, `409 upload_in_progress` ждёт секунду и снова читает `HEAD`. Сеть и 5xx продолжаются с `HEAD`. У `PATCH` таймаут прогресса 30 с без байтов, а не общий таймаут мутации. Одновременно идут не больше двух загрузок. Строка хранит `File`, ключ, id вложения и смещение, поэтому перезагрузка страницы продолжает передачу. `cancel` шлёт `DELETE` и стирает локальное состояние.

## Действия по ошибкам

`describeError` покрывает каждый код `ErrorCode` русской фразой из таблицы `docs/design/api.md` и одним действием: `retry_same_key`, `new_operation`, `restore_connection`, `check_acceptance`, `stop_process`, `sign_in_again`, `reload` или `none`. `actionLabel` пуст, когда действие `none`. Неизвестный код даёт общую русскую фразу с correlation id. Повтор решает поле `retry` конверта, а не код HTTP. Каждый запрос несёт `X-Canterlot-Client: 1` и `X-Correlation-Id`; `redirect` равен `manual`, `credentials` равен `same-origin`. Мутация без ключа идемпотентности не уходит, кроме `PATCH …/content` и `POST …/read`.

## Рендеринг и недоверенное содержимое

Вывод агентов (`TextContent`, инструменты, отчёты) считается полностью недоверенным. Преобразование сырого текста в DOM изолировано в модулях `web/src/lib/render/{markdown,streamingMarkdown,highlight,sanitize,ansi}.ts`, компоненте `web/src/lib/render/Html.svelte` и стилях `web/src/lib/styles/highlight.css`.

Единственная точка использования `{@html}` в приложении — компонент `Html.svelte`. Это ограничение зафиксировано в `token-lint.allow.json`, правилах `eslint.config.js` (`svelte/no-at-html-tags`, `no-restricted-properties` для `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`) и контролируется статическими линт-тестами `tests/unit/render/sinks.test.ts`.

Конфигурация `createMarkdown()`:
- `markdown-it` запускается с `{ html: false, linkify: true }`. Сырые HTML-теги не интерпретируются парсером.
- Ссылки: `validateLink` разрешает только схемы `http:`, `https:`, `mailto:` и `#` после декодирования XML-сущностей, процентного кодирования и удаления управляющих символов. Недопустимые схемы очищаются.
- Все ссылки принудительно получают атрибуты `target="_blank" rel="noopener noreferrer nofollow"`.
- Изображения: синтаксис `![alt](url)` трансформируется в безопасную ссылку `<a>` с текстом alt; генерация тегов `<img>` полностью исключена во избежание трекинга и смешанного содержимого.
- Очистка DOMPurify: строгий список разрешённых тегов (`p h1–h6 ul ol li pre code em strong del blockquote hr table thead tbody tr th td a br span`) и атрибутов (`href title class rel target start`). Каждый токен класса фильтруется до префиксов `hljs*` и `language-*`. Markdown и подсветка используют один собственный экземпляр DOMPurify с общей политикой (`sanitize.ts`), независимо от порядка инициализации и хуков импортируемого singleton. Исключены любые `style`, `srcset`, обработчики событий (`on*`), SVG и MathML.

Потоковый сплиттер `splitStable(text, fromBoundary?)`:
- Выполняет нарезку по пустым строкам (`\n\s*\n`) вне блоков кода (code fences).
- Гарантирует свойство `append-only`: зафиксированная граница никогда не смещается назад при росте потока символов.
- Никогда не разбивает текст внутри открытого блока кода.
- Учитывает fence из backtick или тильд, длину открывающего маркера и отступ до трёх пробелов. Закрывающая строка должна содержать тот же маркер не меньшей длины, после которого допустимы только пробелы и табуляции; backtick в info-строке backtick-fence запрещён. В списках отступ считается относительно контейнера; выход из него завершает вложенный fence перед разбором внешней строки. Поддерживаются LF, CRLF и CR.
- Никогда не ставит границу перед маркером списка (`- `, `* `, `+ `, `1. `, `1) `) или строкой продолжения с отступом от двух колонок, включая одиночную табуляцию, что предотвращает разрушение структуры списков при потоковом приёме.

Потоковый рендерер `StreamingMarkdown`:
- Закрытые стабильные блоки рендерятся один раз и кешируются по содержимому. При каждом обновлении перерендеривается только открытый незавершённый хвост.
- Сплиттер хранит обработанное смещение, состояние незавершённой строки и fence; при дописывании разбирает только новые символы. Массив закрытых блоков и объекты в нём переиспользуются. Замена текста сбрасывает состояние; `splitStable` хранит состояние последнего входа отдельно от экземпляров `StreamingMarkdown`.
- Если хвост превышает 8 КиБ (8192 байта), включается быстрый путь `plain: true` с экранированием HTML без дорогостоящего парсинга markdown.
- Незакрытый блок кода до его завершения отображается как обычный `<pre><code>`.
- По флагу `final: true` выполняется единый полный проход рендера всего блока (`id: "final"`), гарантирующий соответствие монолитному рендеру.

Подсветка синтаксиса `highlightLazy(code, lang)`:
- Ленивый динамический импорт ядра `highlight.js` и нужного языка (поддерживаются rust, typescript, javascript, python, bash, json, yaml, toml, sql, diff, xml, go, css, markdown, svelte→xml).
- Запускается только для закрытых блоков кода.
- Пропускается при превышении лимитов `HIGHLIGHT_LIMITS` (20 480 байт или 400 строк) и для неизвестных языков.
- Выходной HTML подсветки перед передачей в `Html.svelte` пропускается через тот же строгий allow-list DOMPurify.
- Цвета классов `hljs-*` в `highlight.css` привязаны исключительно к семантическим дизайн-токенам (`--text`, `--accent`, `--code`, `--muted`, `--success`, `--warning`, `--blue`), без сырых стилевых значений.

Очистка ANSI `stripAnsi(s)`:
- Линейный сканер удаляет последовательности CSI и OSC с началом ESC или C1, OSC до BEL или ST (ESC `\` либо C1), а также управляющие escape-коды. Незавершённая последовательность удаляется до конца входа; повторные начала последовательностей не запускают повторный поиск по оставшемуся суффиксу.

## Хранилища и правила блоков

Состояние экранов живёт в `web/src/lib/stores`. `applyBlockEvent` — единственное место автомата блока. `block_started` идемпотентен. Дельта применяется только при `base_rev`, равном текущей ревизии; `rev` не больше текущей игнорируется. Дыра (`base_rev` больше текущей) и пересечение уже применённого диапазона переводят блок в `stale` и догружают содержимое: дыра с нулевого байта, пересечение с текущего UTF-8-смещения `block.bytes`. Пока блок `stale`, следующие дельты копятся и после догрузки проигрываются по порядку: ревизии не новее полученной отбрасываются, первая оставшаяся обязана продолжать полученную ревизию, иначе догрузка повторяется. `block_final` заменяет текст целиком и сверяет SHA-256 UTF-8; несовпадение даёт повторную догрузку и диагностику `block_checksum_mismatch`. При `text_omitted` накопленный текст сверяется, только если разрыва не было. Дельта после `final` не меняет текст (`delta_after_final`). `block_incomplete` оставляет частичный текст и причину; поздний финал его заменяет. У `tool_call` до финала виден `summary`, не частичный JSON. Смещения догрузки — байты UTF-8 (`utf8Length`), не единицы UTF-16.

Ввод до `feed_seq` остаётся в полосе под лентой (`saving`, `queued`, `dispatched`, `on_machine`). В ленту он входит один раз, по первому `input_state_changed` в `transmitting`, `accepted`, `acceptance_unconfirmed` или `rejected`, и `feed_seq` равен `scope_seq` этого события. Отмена уходит из ленты и держит короткую пометку в полосе 4 секунды. Локальный `saving` и серверный ввод с тем же ключом идемпотентности — один элемент; ключ снимается с журнала на `input_queued` и на элементе истории.

Окно ленты хранится по возрастанию номера, без повторов ключа, не больше 3000 элементов. Страница старше этого предела срезает новый конец и отцепляет хвост: живые события только увеличивают счётчик, пока `loadNewer` не дочитает `history?after=` от шва и не проиграет буфер по правилам ревизий. `reloadTail` подменяет хвост последней страницей и тоже проигрывает буфер. Снимок заменяет окно; более старые страницы остаются, только если их блоки уже `final` или `incomplete`, а вводы терминальны. Потоковый текст блока из снимка подменяется целиком, без склейки.

`ListStore` сливает атрибуты из `conversation_created` и `conversation_updated`, а летучие поля только из `derived_changed`. Счётчики берутся из снимка и обновляются этими событиями и `group_changed`. `limits_changed` меняет одно окно одного провайдера. `MachinesStore` читает `GET /snapshot/machines` и область `machines`. `hidden` двигает курсор и не доходит до редьюсеров. Неизвестный `kind` считается и не бросает исключение. Зарезервированные `request_*` лежат в `requests` как есть. Отметка прочитанного уходит не чаще раза в 2 секунды и только вперёд по `seq`. Форматтеры `web/src/lib/format/ru.ts` считают локальное время и принимают явный `now`.

## Лента и прокрутка

Лента чата (`web/src/lib/timeline`) не держит историю в DOM. `HeightIndex` хранит высоты строк деревом Фенвика. В документ попадает видимый диапазон плюс запас в полтора экрана, но не больше 80 строк; сверху и снизу стоят распорки. Неизмеренные строки берут оценку по виду, `ResizeObserver` записывает фактическую высоту в следующем кадре. У скроллера `overflow-anchor: none`: перед вставкой старой страницы и перед ростом строки выше окна контроллер запоминает ключ верхней видимой строки и смещение внутри неё, затем возвращает `scrollTop`. Прижатие к низу действует в 48 пикселях от края и снимается только пользовательским сдвигом вверх. Пока лента прижата, рост хвоста прокручивает вниз один раз за кадр; иначе появляется кнопка «К новым сообщениям». Отцепленный хвост (больше 3000 загруженных элементов) показывает «К последним сообщениям» и зовёт `reloadTail`. Сжатие окна, как при клавиатуре, оставляет прижатый чат внизу. Сентинел у верхнего края запрашивает предыдущую страницу истории.

Карточка ответа собирает подряд идущие блоки одного `input_command_id`. Блоки субагента с `parent_id` в основной ленте скрыты и видны строкой «Субагент» со ссылкой на дорожку. Инструмент свёрнут, пока владелец его не откроет; полный текст грузится страницами по 256 КиБ и не раздувает DOM дальше 2 МиБ. Полоса очереди и отложенных сообщений стоит вне живой строки «Генерирует». Журнал ленты имеет `aria-live="off"`; одна вежливая область объявляет смену фазы, не каждый токен. Текст блока попадает в DOM не чаще одного раза за кадр.

## Правила ввода и черновики

Поле ввода (`web/src/lib/composer`) изолирует логику работы с текстом, правилами отправки, черновиками и действиями очереди (Task 6a).

Правила клавиши Enter (`sendRules.ts`):
- На сенсорных устройствах (`pointer: coarse` или последнее касание `touch`) при настройке `auto` или `newline` нажатие Enter всегда добавляет перевод строки (`newline`). Отправка сообщения с сенсорного экрана возможна исключительно через явное нажатие кнопки отправки (защита от случайных отправок на телефонах, Review Focus 2).
- На рабочем столе (`mouse` или физическая клавиатура) при `auto`: Enter отправляет сообщение, Shift+Enter переносит строку.
- Пользовательская настройка `canterlot.enter` в `localStorage` принимает значения `auto`, `send` (Enter отправляет, Shift+Enter переносит) или `newline` (Enter всегда переносит строку).
- IME-композиция (`isComposing: true` или `keyCode: 229` у экранных клавиатур Android и Samsung) всегда игнорируется (`ignore`): клавиша Enter, завершающая выбор иероглифа или подсказки, не приводит к отправке или переносу.
- Сочетание Ctrl/Cmd+Shift+Enter открывает меню «Отправить позже» (`send_later_menu`) и никогда не отправляет ввод сразу.

Затвор отправки (`SendGate` в `model.svelte.ts`):
- В соответствии со спецификацией (§12.2) неактивное состояние кнопки отправки всегда сопровождается видимой причиной на русском языке:
  - Пустой текст без вложений: «Введите сообщение или прикрепите файл».
  - Загрузка вложений в процессе: «Файлы ещё загружаются (N из M)».
  - Превышение размера текста: «Текст длиннее 256 КиБ» (подсчёт байтов UTF-8 через `utf8Length` выполняется только в случае, если длина строки, умноженная на 3, может превысить 262 144 байта).
  - Переполнение очереди сессии (`chat.queue.queued >= queue_limit`): «Очередь заполнена ({limit}): дождитесь выполнения» с сохранением текста в поле ввода.

Порядок отправки (P-01, I-1):
1. Проверяется условие затвора `gate.ok` и защита от повторной активации в течение 600 мс.
2. Проверяется доступность сети `canSendNow()`: смотрит на `navigator.onLine` и свежий HTTP 200 (или пробу `GET /api/v1/me`), живость WebSocket не учитывается. При офлайне выводится сообщение «Нет связи: сообщение сохранено как черновик и не отправлено», черновик сохраняется, локальная операция в журнале не создаётся.
3. В том же кадре создаётся локальный элемент `InputView` в состоянии `saving` и помещается в полосу (`chat.inputs.set`), фиксируются метки `probe.mark('send_pressed')` и `probe.mark('input_painted')`.
4. Операция с уникальным ключом идемпотентности записывается в IndexedDB через `ops.begin('input', …, persist: true)`. При ошибке записи текст восстанавливается в поле ввода с сообщением «Не удалось сохранить на устройстве».
5. Поле ввода и черновик очищаются.
6. Запускается операция `ops.run(op)`. В случае однозначного отказа сервера (`op.state === 'refused'`) текст возвращается в черновик и в поле ввода, а ключ идемпотентности удаляется из активных вводов. При исходе `unknown` сохраняется тот же ключ идемпотентности, состояние отражается в полосе с возможностью ручного повтора.

Отложенные сообщения (`schedule.ts`):
- Валидация времени `validateScheduleTime(at, now)` следует окну хаба: `now + 1 с <= run_at <= now + 366 дней`, используя скорректированные серверные часы `clock.serverNow()`.
- Быстрые варианты `presets(now)`: «Через 15 минут», «Через час», «Сегодня вечером» (18:00 местного времени текущего дня или следующего дня, если 18:00 уже наступило) и «Завтра утром» (09:00 следующего дня).

Действия очереди (`timeline/QueueActions.ts`):
- `cancelInput(input)`: отправляет `POST /api/v1/inputs/{id}/cancel` с ключом идемпотентности. Обрабатывает исходы Delivery D3: подтверждённая отмена (`cancelled`), запрос отмены исполнителю (`requested`, флаг `cancelRequested`) и невозможность обычной отмены из-за начавшейся передачи (`lost`).
- `retryAsNew(input)`: после подтверждения предупреждения о повторном действии генерирует новый ключ идемпотентности и отправляет запрос с `retry_of`, указывающим на неподтверждённый ввод (A4 G10).
- `returnToDraft(input)`: восстанавливает текст и вложения отклонённого сообщения обратно в черновик и удаляет элемент из активных вводов.
